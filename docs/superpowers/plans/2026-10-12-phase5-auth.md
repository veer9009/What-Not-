# Phase 5 authentication implementation plan

User authorization: inspect first, then implement directly unless a critical
architecture conflict or destructive/schema migration is required. Work in the
existing master checkout; do not commit or push. This overrides skill approval,
worktree, and commit gates. No migration is needed.

## Design

Keep Route -> Service -> Repository -> PostgreSQL. Add Argon2id password helpers,
PyJWT HS256 access tokens, public auth service, transaction-scoped request
dependencies and safe HTTP error handlers. Tokens contain sub/iat/exp only;
database role and active status govern every authenticated request. Secret comes
from WHAT_NOT_JWT_SECRET_KEY, algorithm is restricted to HS256, lifetime defaults
to 15 minutes (configurable 1..60). Production settings reject missing secrets;
development health/docs still work without configuration, auth fails closed.

Public registration requires name/email/phone/password and BUYER or SELLER.
Normalize new email to lowercase and trim phone without guessing country formats.
Case-insensitive existing email lookup rejects ambiguous legacy identities, rather
than selecting an account arbitrarily. No schema uniqueness change. Registration
creates only a User; separate SELLER-only profile creation requires complete data.
Argon2id hashes only for new passwords; verify existing bcrypt and upgrade on
successful login. Unknown/inactive/bad credentials share 401 and dummy verification.

One explicit outer transaction begins before authenticated database reads and
commits before returning a response. Services retain their savepoints/locks.
Authentication checks token before obtaining storage; role dependencies read the
current database user. Responses are explicit schemas and omit hashes. Validation
errors omit submitted input to prevent password/token echo. SQL failures are generic.

Activate auth register/login/me, seller product writes, seller profile CRUD/product
listing, own address CRUD/default, owned order read/list/transitions, admin moderation.
Leave product discovery/detail and order placement 501: geography is absent.

1. Add failing HTTP auth/security tests under existing isolated persistence harness;

2. Add pinned argon2-cffi/PyJWT/bcrypt, security helpers, settings, schemas, auth
   service and dependencies. Verify hashing, JWT validation, registration/login/me.
3. Add failing role/ownership/rollback tests; activate only supported secure routes.
   Map domain errors to 401/403/404/409 and sanitize infrastructure/validation errors.
4. Update old placeholder tests for the intentional contract changes. Add integration
   coverage for complete seller/moderation/order/address workflows, stale roles,
   deleted/inactive accounts, spoofed actor fields, duplicate/ambiguous identities.
5. Review the complete diff and authorization boundary; fix security regressions
   with failing tests. Document decisions, routes, concepts, limits and Ravi's flow.
6. Run full warning-strict pytest, auth/authorization selection, persistence/service/
   concurrency selection, isolated migration round trip/metadata check, compileall,
   pip check, git diff --check, frontend tests, tsc and build. Record exact results
   in backend/PHASE5_REPORT.md. Keep all changes uncommitted.

## Review focus

- Missing/invalid tokens must fail before database access.
- Body/path identity cannot bypass ownership; token role cannot grant privileges.
- Case-insensitive identity normalization must not authenticate ambiguous old rows.
- No submitted password or unknown sensitive field may appear in 422 responses.
- Commit failures must roll back and produce a generic error before response delivery.
- All database validation uses only the existing generated local test cluster.
